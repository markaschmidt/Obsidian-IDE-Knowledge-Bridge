## Important distinctions

Version 0.3 uses the documented MCP Apps surface in [Cursor](https://cursor.com/docs/mcp) and [VS Code](https://code.visualstudio.com/api/extension-guides/ai/mcp). A tool advertises a `ui://` HTML resource, while the [Apps SDK](https://apps.extensions.modelcontextprotocol.io/api/documents/Quickstart.html) bridges UI-only tools and explicit user messages. The same browser UI runs in an editor webview when chat embedding is unavailable. This yields shared controls without depending on private native composer APIs.

The [MCP completion contract](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/completion) supports dependent arguments through `context.arguments`. The optional native prompt chains vault and document suggestions. VS Code documents argument dialogs; Cursor's exact completion presentation remains unverified. This is separate from the shared multi-document chip builder. Native participant-variable completion appears in [VS Code proposed declarations](https://github.com/microsoft/vscode/blob/main/src/vscode-dts/vscode.proposed.chatParticipantAdditions.d.ts); [proposed APIs](https://code.visualstudio.com/api/advanced-topics/using-proposed-api) are not a stable Marketplace contract and are not used.

The v0.2 chat flow uses [Cursor skills](https://cursor.com/docs/skills) and [VS Code skills](https://code.visualstudio.com/docs/agent-customization/agent-skills), both of which discover `.agents/skills/`. A skill named `obsidian` with `disable-model-invocation: true` supplies the explicit slash command. The [MCP elicitation contract](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation) supplies flat forms for vault selection and document checkboxes; Cursor and VS Code document elicitation support. This is a post-submit tool interaction, not an API for changing either host's private composer UI. Primitive checkbox fields retain compatibility with older form clients. Prompt-file-only integrations and undocumented chat attachment commands are not required.

MCP is the agent-facing integration; the extension provides settings and editor actions. Neither replaces the other. Dynamic extension registration does not by itself configure an independent CLI process. The export command therefore generates explicit arguments for the same profile.

Cursor's public APIs do not imply unrestricted access to an editor's entire private chat store. No private session database is read. Explicit captures and MCP handoffs form the first portable workflow. Hook-based final-response drafts can be added after consent, redaction, retention and payload compatibility are specified. Do not capture hidden reasoning events.

Obsidian's native metadata graph provides richer host semantics than a standalone Markdown parser. The companion uses it for native neighbors, but the server still filters every result by workspace policy. Full offline/native graph parity is an acceptance item, not an implemented claim.

The Rhen review uses the owner-provided local plugin source as an integration reference only; [RHEN.md](RHEN.md) records the minimal compatibility facts and limitations without publishing private code.
